# Custom Provider

Besides the [built-in providers](/docs#supported-providers), a custom defined provider that extends [`AiohaBaseProvider` class](https://github.com/aioha-hive/aioha/blob/main/src/providers/provider.ts) may be registered. This may be useful for backend use or development of another browser provider.

## Registering Custom Providers

`registerCustomProvider()` supports two forms:

<Tabs>
  <TabItem value="named-form" label="Named (Recommended)" default>
    Register a provider under an arbitrary name. Multiple custom providers can be registered concurrently, each with a unique name. Use the same name when calling `login()`, `switchUser()`, or any other provider-aware method.

    ```js
    const aioha = new Aioha()

    // Register a custom provider under the name 'beekeeper'
    aioha.registerCustomProvider('beekeeper', new BeekeeperProvider(...))

    // Login with the named custom provider
    const login = await aioha.login('beekeeper', 'your-username', { msg: 'Hello World' })
    ```

    **Constraints:**
    - `name` must be a non-empty string
    - `name` must not collide with a built-in provider name (e.g. `'keychain'`, `'hiveauth'`, `'hivesigner'`, `'ledger'`, `'peakvault'`, `'metamasksnap'`, `'viewonly'`)
    - `name` must not already be registered — call [`deregisterProvider()`](#managing-custom-providers) first to replace
    - The literal `'custom'` is explicitly allowed (it maps to the legacy `Providers.Custom` slot)

    **`keyType` bypass:** Named custom providers skip the `keyType` requirement in login options, so you can omit it when calling `login()`.

    **Implementation requirement:** For `switchUser()` to round-trip correctly, your custom provider's `getLoginInfo()` must return the same `provider` name it was registered under. For example:

    ```js
    class MyProvider extends AiohaProviderBase {
      getLoginInfo() {
        return { provider: 'my-provider-name', pubKey: 'STM...' }
      }
    }
    ```
  </TabItem>
  <TabItem value="legacy-form" label="Legacy (Providers.Custom)">
    Register a single provider under the `Providers.Custom` enum value (`'custom'`). Only one provider can be registered this way at a time.

    ```js
    const aioha = new Aioha()
    aioha.registerCustomProvider(new BeekeeperProvider(...))

    const login = await aioha.login(Providers.Custom, 'your-username', { msg: 'Hello World' })
    ```

    This form is kept for backward compatibility. The named form above is recommended for new code.
  </TabItem>
</Tabs>

### Multiple Custom Providers

You can register and use several custom providers side by side:

```js
const aioha = new Aioha()

// Register two custom providers
aioha.registerCustomProvider('beekeeper', new BeekeeperProvider(...))
aioha.registerCustomProvider('hardware-x', new HardwareXProvider(...))

// Login as alice via beekeeper
await aioha.login('beekeeper', 'alice', {})

// Switch to bob via hardware-x
await aioha.login('hardware-x', 'bob', {})

// Switch back to alice — restores the beekeeper provider
aioha.switchUser('alice')
console.log(aioha.getCurrentProvider()) // 'beekeeper'
```

### Managing Custom Providers

Custom providers work with all provider management methods:

```js
// Check if a custom provider is registered
aioha.isProviderRegistered('beekeeper') // true

// List all registered providers (includes custom names alongside built-in ones)
aioha.getProviders() // ['beekeeper', 'hardware-x', 'keychain', ...]

// Deregister a custom provider (must be logged out first)
aioha.deregisterProvider('beekeeper') // true
```

## Beekeeper Signer

The recommended signer for backend usage is the [`BeekeeperProvider`](https://github.com/aioha-hive/aioha/blob/main/src/providers/custom/beekeeper.ts), which delegates key storage and signing to a [Beekeeper](https://gitlab.syncad.com/hive/beekeeper) wallet. Private keys never leave the wallet — the provider only holds public keys and passes digests to the wallet for signing.

### Installation

```sh
pnpm i @aioha/aioha @hiveio/beekeeper
```

### Usage

```js
import { Aioha, AiohaClient, KeyTypes } from '@aioha/aioha'
import { BeekeeperProvider } from '@aioha/aioha/build/providers/custom/beekeeper.js'
import { SimpleEventEmitter } from '@aioha/aioha/build/lib/event-emitter.js'
import createBeekeeper from '@hiveio/beekeeper'

// Initialize a beekeeper wallet and import the private key
const bk = await createBeekeeper({ inMemory: true })
const session = bk.createSession('some-salt')
const { wallet } = await session.createWallet('my-wallet', 'password', true)
const pubKey = await wallet.importKey('5somethingsomething')

// Register the beekeeper provider under a custom name
const aioha = new Aioha()
aioha.registerCustomProvider(
  'beekeeper',
  new BeekeeperProvider(
    wallet,
    { [KeyTypes.Posting]: pubKey, [KeyTypes.Active]: pubKey },
    new AiohaClient(),
    new SimpleEventEmitter()
  )
)

// Login with the named custom provider
const login = await aioha.login('beekeeper', 'your-username', { msg: 'Hello World' })

// Claim rewards
const claim = await aioha.claimRewards()
console.log(claim)
```

The `keys` map associates a [`KeyTypes`](https://github.com/aioha-hive/aioha/blob/main/src/types.ts) entry (`Posting`, `Active`, `Owner`, `Memo`) with the public key of the corresponding private key held in the wallet. Only key types present in the map can sign — attempting to use a missing key type throws.

:::tip Custom SHA-256 implementation
The constructor accepts an optional fifth argument to supply your own SHA-256 function (e.g. `sha256` from [`@noble/hashes`](https://github.com/paulmillr/noble-hashes)). If omitted, the browser-compatible default from Aioha is used.
:::

:::warning Persistent wallets
Use `inMemory: true` for ephemeral sessions only. For persistent storage, omit the flag and supply `storageRoot` — see the [Beekeeper docs](https://www.npmjs.com/package/@hiveio/beekeeper) for configuration.
:::

## Plaintext Private Key

:::danger Deprecated
`PlaintextKeyProvider` is deprecated in favor of the [Beekeeper signer](#beekeeper-signer). It holds the WIF in memory and should not be used in new code.
:::

```js
import { Aioha } from '@aioha/aioha'
import { PlaintextKeyProvider } from '@aioha/aioha/build/providers/custom/plaintext.js'

const aioha = new Aioha()
aioha.registerCustomProvider('plaintext', new PlaintextKeyProvider('5somethingsomething'))

const login = await aioha.login('plaintext', 'your-username', { msg: 'Hello World' })
```
